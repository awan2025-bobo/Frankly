2026-10-19 - awan2025's Claude - Fix tap clicks (first tap, fast taps); remove sizzle
  What changed:
    - src/lib/sounds.ts (rewritten):
        * Clicks are preloaded at app start (preloadSounds), so the first tap
          isn't silent. Before, the file only started loading on the first tap.
        * 4 click players take turns, so fast taps overlap instead of
          cutting each other off. Before, one player was rewound on every tap,
          which cut off the previous click and on phones could drop taps.
        * Each player is rewound to 0.13s (past the file's silence) while
          idle, 250ms after it plays, so a tap only calls play(). Before, it
          rewound right at tap time, which is slow on phones.
        * Sizzle removed (useSizzle and its fade/loop code).
    - src/app/_layout.tsx: calls preloadSounds() once on startup.
    - src/components/Veggies.tsx, Loaders.tsx: removed the useSizzle calls.
    - src/app/(tabs)/profile.tsx: Sounds switch subtitle -> "A soft click
      when you tap".
  Why: awan2025 didn't like the sizzle; some taps had no click (often the
       first), and fast tapping cut sounds off.
  Notes:
    - assets/sounds/sizzle.mp3 is still in the folder but unused (nothing
      loads it). Delete it or swap in a new sizzle later.
    - Tested on web (headless Edge, logging every audio play/pause): first tap
      after load played with the file fully loaded; 10 taps 60ms apart gave
      10 full clicks spread across the 4 players, none cut off. Type-check
      passes. Not yet tested on a real phone.

2026-10-19 - awan2025's Claude - Sound effects: tap click + sizzling pan
  What changed:
    - assets/sounds/click.mp3, sizzle.mp3: sounds picked by awan2025.
    - expo-audio ~57.0.5 added (npx expo install; app.json gets its config
      plugin). Works in Expo Go and on web. AFTER PULLING: run npm install.
    - src/lib/sounds.ts (new): all sound logic in one place.
        playClick(): plays click.mp3 from 0.13s - the file has 0.14s of
          silence before the click (measured), so skipping it makes taps feel
          instant. Volume 0.6.
        useSizzle(on): loops sizzle.mp3 for as long as `on` is true, fading in
          (0.4s) and out (0.5s). The file is 27.8s; animations shorter than
          that just fade out early, longer waits loop seamlessly. So the sound
          always matches the animation length - no file editing needed.
        Sounds on/off setting, saved on the device (AsyncStorage
          "frankly.sounds"). Respects the iPhone silent switch and lets music
          from other apps keep playing.
    - src/components/Pressable.tsx (new): React Native's Pressable + the click.
      Every file that used Pressable from 'react-native' now imports this one
      (ui.tsx, TabBar, RecipeView, BookShelf, StepHelper, ApplianceGrid and
      the screens), so every button, chip, tab and checkbox clicks - and new
      ones will too. Tap-outside-to-close backdrops use sound={false}.
    - src/components/Veggies.tsx: Home pot sizzles for the whole "cooking"
      stage (useSizzle(cooking)), fading out when the recipe pops.
    - src/components/Loaders.tsx: SizzlingPan ("Building your Frankly...")
      sizzles while on screen.
    - src/app/(tabs)/profile.tsx: Settings has a "Sounds" on/off switch.
  Why: add sound effects; sounds of any length should fit the animation.
  Notes:
    - New tappable things: import { Pressable } from '@/components/Pressable'
      (not from 'react-native') to get the click.
    - Adding a sound: put the file in assets/sounds, add a player in
      src/lib/sounds.ts next to the click/sizzle ones.
    - Tested on web (demo mode, headless Edge, logged every audio play/pause):
      each tap played click from 0.13s; sizzle started with the building
      screen and the Home pot, and paused after fading out when each ended.
      Type-check passes. Not yet heard on a real phone.

2026-10-19 - awan2025's Claude - New launcher: web link first, QR code on a page
  What changed:
    - scripts/dev.mjs (new): starts Expo (`expo start --lan` by default), hides
      the big terminal QR code (EXPO_NO_QR_CODE), waits until Metro is ready,
      then prints:
        Web:          http://localhost:<port>  - the app in the browser
        Phone QR:     http://localhost:8090    - a small page with a QR code;
                      scan it with the phone Camera to open Expo Go
        Expo Go link: exp://<wifi-ip>:<port>   - same link as text
      It picks the laptop's Wi-Fi IP (skips VPN/virtual adapters) and passes it
      to Expo via REACT_NATIVE_PACKAGER_HOSTNAME, so the QR code always matches
      the address Expo serves. If port 8081 is taken it uses the next free one.
    - package.json: added script "dev" -> node scripts/dev.mjs.
  Why: wanted a web version link up front and the QR code as a link instead
       of filling the terminal.
  Notes:
    - Run: npm.cmd run dev   (Mac: npm run dev). The old way,
      npx.cmd expo start --lan --clear, still works unchanged.
    - Extra flags pass through to Expo: npm.cmd run dev -- --clear
    - --tunnel keeps Expo's own terminal QR code (tunnel URL comes from Expo).
    - Wrong IP picked? Set it by hand: $env:FRANKLY_HOST="192.168.x.x"
    - The QR page draws the code with a script from cdnjs, so the laptop needs
      internet; offline, it shows the exp:// link to type into Expo Go.
    - Tested: web and iOS bundles both build and load (1045 / 1440 modules),
      QR page serves the right exp:// link, phone manifest reports the Wi-Fi IP.
    - Web runs the same screens; phone-only features (haptics, location
      permission prompts) may behave differently in a browser.
